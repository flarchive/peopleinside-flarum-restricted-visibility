# Security Policy

## Supported versions

This project targets Flarum 2.x.

| Version | Security support |
| --- | --- |
| 1.x | Not supported |
| 2.x | Current target |

Security fixes, when available, will be published through the project's GitHub repository and package releases.

## Reporting a vulnerability

If you believe you have found a security vulnerability in Restricted Visibility, please do not publish exploit details in a public GitHub issue.

Please contact the maintainer privately:

**Email:** [tickets@peopleinside-it.p.tawk.email](mailto:tickets@peopleinside-it.p.tawk.email)

**HelpDesk** https://helpdesk.peopleinside.it

Use a descriptive subject such as `Private security report – Restricted Visibility`.

Include, where possible:

- The affected extension version.
- The Flarum and PHP versions.
- A concise description of the issue and its potential impact.
- Reproduction steps or a proof of concept that does not expose real users' data.
- Any relevant logs with passwords, tokens, personal data, and other secrets removed.

Please allow the maintainer reasonable time to investigate and prepare a fix before disclosing the issue publicly.

## Scope and limitations

This policy covers security issues in the Restricted Visibility extension itself.

Issues caused by Flarum core, server configuration, hosting providers, or third-party extensions may need to be reported to their respective maintainers as well.

Do not include real private content, personal data, credentials, session cookies, or production database dumps in a report.
